# Задача 1-1

Заметим, что если в $B$ уберем из аргумента мат.ожидания $\max$, получим
$$
B=\mathbb E_r \left[\max_{I\in\mathcal I} t_r(I)\right] \geq \mathbb E_r [t_r(I)]\quad\forall I
$$
Откуда и следует, что раз оно не меньше всех величин, значит не меньше и максимума
$$
B \geq \max_{I\in\mathcal I} \mathbb E_r[t_r(I)] = A.
$$

# Задача 1-2

Для начала можно понять, что самой неглубокой веткой будет конкретизация любой заранее выбранной перестановки массива. Не ограничивая общности, можем считать, что этот алгоритм конкретизирует тождественную перестановку. Тогда, самым коротким путем будут решения:

$\boxed{a_1 \leq a_2} \xrightarrow{\text{yes}} \boxed{a_2 \leq a_3} \xrightarrow{\text{yes}} \dots \xrightarrow{\text{yes}} \boxed{a_{n-1} \leq a_n} \xrightarrow{\text{yes}} (1,2,\dots, n)$.

Это соответствует функции $g(n) = n-1$, если считаем количество ребер от корня до листа. Такой конструктивный подход доказывает достижимость оценки.

При этом конкретизировать перестановку нельзя менее чем за $n-1$ сравнение. Это можно увидеть так. Например, изначально у нас $n$ групп элементов:

$\{x_1\}, \{x_2\}, \dots, \{x_n\}$

После сравнения элемента из одной группы $x_i\in G_1$ с любым из элементов другой группы $x_j\in G_2$ можем объединить эти группы в одну $G_1 \cup G_2$. После $n-2$ сравнений останется минимум 2 группы (т.к. после каждого сравнения группы уменьшаются не более чем на одну); таким образом можно будет предъявить 2 перестановки. В одной будут идти сначала элементы из группы $G_1$ (не противореча сравнениям внутри группы), а потом из группы $G_2$. В другой перестановке наоборот.

# Задача 1-3

Можно отождествить решение задачи с последовательностью 0 и 1 длины $n+m$, которые говорят элемент из какого массива надо брать следующим. Например, для массивов $A, B$ пследовательность $(0, 0, 1, 0, 1)$ (здесь опущено требование $m\geq 2n$, это не имеет значения) будет означать, что смердженный массив будет иметь вид $(A_1, A_2, B_1, A_3, B_2)$.

Так как алгоритм должен будет отвечать в том числе на массивах, когда повторений элементов нет, будем считать, что в каждом листе лежит только одно такое сочетание, и тогда ограничение снизу на число сравнений будет как наименьшая высота дерева, который содержит в себе $C_{n+m}^n$ листьев:
$$
\log_2 C_{n+m}^n
$$
Рассмотрим подробней сочетания
$$
C_{n+m}^n = \frac{(n+m)!}{n!m!} = \frac{(m+1)\dots(m+n)}{n!} \geq \left(\frac mn\right)^n
$$
Здесь заменили в числителе все элементы $(m+1), \dots, (m+n)$ на меньшие - $m$, а в знаменателе все элементы $1,\dots,n$ на большие - $n$. Логарифмируя левую и правую часть получаем
$$
\log_2 C_{n+m}^n = \Omega\left(n\log\frac mn\right)
$$

# Задача 1-4

#### 1 часть

Т.к. среднее - это интеграл по множеству меры 1, можно видеть, что:
$$
\min_{A\in\mathcal A} \mathbb E_I [f_A(I)] \leq \mathbb E_A[\mathbb E_I[f_A(I)]]
$$
$$
\mathbb E_I[\mathbb E_A[f_A(I)]] \leq \max_{I\in\mathcal I} \mathbb E_A [f_A(I)]
$$

Заметим, что для конечных распределений $P(x)$ и $P(y)$ справедливы следующие выкладки
$$
\mathbb E_x [\mathbb E_y [f(x,y)]] = \sum_{x} P(x) \sum_{y} f(x,y)P(y|x) = \sum_{x,y} f(x,y) P(y|x)P(x)
$$
Из определения условного мат.ожидания $P(y|x)P(x)=P(x|y)P(y)$ и тогда сумма переписывается
$$
\sum_{x,y} f(x,y) P(x|y)P(y) = \sum_y P(y) \sum_x f(x,y) P(x|y) = \mathbb E_y [\mathbb E_x [f(x,y)]]
$$
А значит, что $\mathbb E_I [\mathbb E_A[...]] = \mathbb E_A [\mathbb E_I[...]]$, откуда и получается требуемое неравенство.

В требуемых в условиях задачи терминах это неравенство можно сформулировать следующим образом:

Рандомизированная сложность алгоритма в худшем случае (на худшем входе) не может быть меньше, чем сложность в среднем (при любом распределении входов) на лучшем из детерминированных алгоритмов.

#### 2 часть

Назовем вероятностное распределение на конечном множестве решающих деревьев сортировки (лес) рандомизированным алгоритмом сортировки в модели решающих деревьев. Рандомизированным на практике алгоритмы делает какой-нибудь seed конечного типа, поэтому в определении и предполагается конечность леса.

Обозначим за $f_A(I)$ количество сравнений, требуемых дереву $A$ для определения перестановки входа $I$. Оценим теперь для фиксированного дерева $E_I [f_A(I)]$. Так как оцениваем произвольный рандомизированный алгоритм, выберем худшее распределение $I$ - равномерное на всех $n!$ входах.

Рассмотрим в произвольном бинарном дереве сколько вершин могут находится на высоте ниже, чем $\log_2 n! - 1$: на высоте 0 лежит не более 1 вершины, на высоте 1 не более 2, и так далее:
$$
1 + 2 + \dots + 2^{\log_2 n! - 2} = 2^{\log_2 n! - 1} - 1 \leq \frac{n!}2
$$
Следовательно, $P(h\geq\log_2 n! -1) \geq \frac12$, а значит
$$
\mathbb E_I[f_A(I)] \geq \frac12\log_2 n!
$$
$$
\mathbb E_I[f_A(I)] = \Omega(n\log n)\quad\forall A
$$
$$
\min_{A\in\mathcal A} \mathbb E_I[f_A(I)] = \Omega(n\log n)
$$
В силу неравенства из пункта 1 получаем
$$
\max_{I\in\mathcal I} \mathbb E_A [f_A(I)] \geq \min_{A\in\mathcal A} \mathbb E_I[f_A(I)] = \Omega(n\log n)
$$
А значит количество сравнений оценивается снизу как $\Omega(n\log n)$, что и требовалось доказать.

# Задача 1-5

Для определенности будем считать, что емкость (`capacity`) отличается от фактического размера (`size`) не более чем в 4 раза. В таком случае предлагается следующая реализация функций добавления и удаления элемента:

```c++
void push(s<T> stack, T elem) {
	if (stack.size < stack.capacity) {
		// стандартное добавление в конец
		stack.size += 1;
	} else {
		stack.capacity *= 2;
		// переброс данных в новую подряд идущую память размера capacity
		// стандартное добавление в конец в новом участке
		stack.size += 1;
	}
	return;
}
```

```c++
T pop(s<T> stack) {
	if (4 * stack.size > stack.capacity) {
		// извлечение последнего элемента в переменную last
		stack.size -= 1;
	} else {
		stack.capacity /= 2;
		// переброс данных в новую подряд идущую память размера capacity
		// извлечение последнего элемента в переменную last
		stack.size -= 1;
	}
	return last;
}
```

Докажем, что если над стеком выполнять только эти 2 операции в любой комбинации (кроме pop на пустой стек, так как в функциях для простоты это не учитывается) амортизировано получается константа времени. Доказывать будем методом монетки.

Можно каждый `pop` требовать по 2 монетки, а каждый push по 3 (либо для однородности требовать всегда по 3 монетки, но для понимания метода лучше разделить, учитывая, что это в любом случае две константы).

Для простоты также считаем, что емкость массива всегда кратна двум и не меньше 4. Предлагаемый инвариант:

- если `size < capacity / 2`, то монетки лежат на таком количестве элементов, сколько не хватает до `size = capacity / 2`
	- $\implies$ `bank = capacity / 2 - size`
- если `size > capacity / 2`, то по 2 монетки лежит на каждом элементе, который превышает `size = capacity / 2`
	- $\implies$ `bank = 2 * size - capacity`
- если `size = capacity / 2`, то `bank = 0`

Теперь проверим сохранение инварианта при операциях:

- если вызван `push` и при этом `size < capacity / 2`
	- убираем монету с одного элемента, тратим её на добавление элемента в конец, а выданные 3 монеты можем выбросить;
	- `size' = size + 1`
	- `bank = capacity / 2 - size`
	- `bank' = bank - 1 = capacity / 2 - (size + 1) = capacity / 2 - size'`
- если вызван `push` и при этом `size >= capacity / 2`
	- монету тратим на добавление элемента, 2 монеты кладем на только что добавленный элемент, т.е. потратили все 3 выданные монеты;
	- `size' = size + 1`
	- `bank = 2 * size - capacity`
	- `bank' = bank + 2 = 2 * (size + 1) - capacity = 2 * size' - capacity`
- если вызван `push` и при этом `size = capacity`
	- `bank = 2 * size - size = size`
	- выделяем новую память и все монеты из банка тратим на перенос элементов в новую память
	- сведено к случаю `size = capacity / 2`
- если вызван `pop` и при этом `size < capacity / 2`
	- тратим монету на удаление элемента, кладем монету на любую монету, лежащую до четверти емкости;
	- `size' = size - 1`
	- `bank = capacity / 2 - size`
	- `bank' = bank + 1 = capacity / 2 - (size + 1) = capacity / 2 - size'`
- если вызван `pop` и при этом `size >= capacity / 2`
	- тратим монетку на удаление элемента, убираем 2 монетки с только что удаленного, и выкидываем лишние монетки в мусор (всего лишними окажутся 3 монетки);
	- `size' = size - 1`
	- `bank = 2 * size - capacity`
	- `bank' = bank - 2 = 2 * (size - 1) - capacity = 2 * size' - capacity`
- если вызван `pop` и при этом `size = capacity / 4`
	- `bank = capacity / 2 - capacity / 4 = size`
	- выделяем новую память и переносим за весь банк элементы в новое место
	- сведено к случаю `size = capacity / 2`

Все операции уложились в 2-3 монеты, значит амортизировано они работают за константу. При этом в доказательстве не учитывался контекст (какие операции выполнялись до, всё это учитывается банком), а значит это справедливо при любой комбинации `push` и `pop`.

# Задача 1-6

Аналогично стеку производить расширение и уменьшение массива. При этом, так как удаление происходит с разных сторон можно завести новую переменную `start`, равную индексу первого добавленного и не покинувшего очередь. Тогда имеем следующие реализации функций:

```c++
void push(queue<T> que, T elem) {
	// контролируем переполнение также как в случае стека
	// при переносе данных переносим циклом new[i] = old[(start+i)%cap]
	// затем start = 0
	// далее приведен код, когда уверены, что переполнения нет
	size_t last_idx = (que.start + que.size) % que.capacity;
	que.data[last_idx] = elem;
	que.size += 1;
}
```

```c++
T pop(queue<T> que) {
	// аналогичный контроль, что в массиве не слишком много
	// свободного места, в ином случае аналогично стеку переносим
	// элементы в новую память так, чтоб start=0
	T popped = que.data[que.start];
	que.start = (que.start + 1) % que.capacity;
	que.size -= 1;
	return popped;
}
```

Реализация аналогична во многом стеку, где было доказана амортизированная константа операций, здесь добавились константные добавки к каждой операции, поэтому нетрудно видеть, что амортизированная константа сохранилась.
